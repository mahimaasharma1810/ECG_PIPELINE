# Examples — runnable inputs and output-format references

Everything in `data/raw/` is gitignored (too large, and patient data), so a
fresh clone has nothing to run the pipeline against. This directory holds the
minimum needed to verify an install end to end, plus one example of each
output format so you can see what the system produces without generating it.

---

## 1. Run inference on a real recording

```bash
# VitalPatch (single-lead wearable, 125 Hz, raw ADC counts).
# This file splits into 2 gap-separated segments; segment 1 is the one the
# example validation report documents.
python3 run_inference.py \
    --input examples/data/vitalpatch/Patch_184B27/1780171482351_VC2B008BF_184B27_ecg.csv \
    --segment-index 1 \
    --output /tmp/report.json

# Expected: risk_level=CRITICAL  n_beats_detected=127
```

```bash
# ProRhythm / SeNSiO (100 Hz). Short file -- 11 beats, exercises the
# low-beat-count path where the pipeline reports LOW rather than asserting.
python3 run_inference.py \
    --input examples/data/prorhythm/ECG_2026-07-07T12-21-42.647304.csv \
    --source prorhythm \
    --output /tmp/report_pr.json

# Expected: risk_level=LOW  n_beats_detected=11
```

Add `--narrative` to either to include the deterministic narrative in the JSON.

**Directory layout matters for VitalPatch.** `parse_vitalpatch_ecg` derives
`patient_id` from the *parent folder* name, which is why the file sits under
`vitalpatch/Patch_184B27/` rather than flat in `data/`. Flatten it and the
segment ID comes out as `vitalpatch/data/...` instead of
`vitalpatch/184B27/...`.

## 2. Output-format references

| File | What it shows |
|---|---|
| `reports/184B27_..._validation_report.pdf` | 6-page clinician validation form — signal quality, rule trace with threshold provenance, ECG strips with beat markers, fillable ground-truth section. Generated by `scripts/generate_validation_pdf.py` from the VitalPatch file above. |
| `reports/clinician_beat_review_example.pdf` | Per-beat review format — individual beat windows with the model's label and confidence, for beat-level ground-truth collection. Generated by `scripts/annotation/generate_review_batch.py`. |

**JSON report format**, including the MedGemma narrative fields (`narrative`,
`medgemma`), is in `ecg_pipeline/example_reports/` — 8 reports covering both
VitalPatch and MIT-BIH WFDB sources.

## 3. What these are not

- **Not a test fixture.** No expected-output file is committed, so nothing here
  fails a CI check. `tests/test_pipeline_synthetic.py` is the actual regression
  test and needs no external data.
- **Not a representative sample.** Two recordings from two devices. The
  CRITICAL verdict on the VitalPatch file reflects that segment, not a base
  rate — see `docs/CLASSIFIER_EVAL_MITDB_SVDB_2026-08-03.md` for measured
  classifier performance.
- **Not calibrated.** Amplitudes are raw device ADC counts; neither device
  publishes a mV-per-count constant.

To work with the full corpus, see `docs/thesis/DATASETS.md` and the download
commands in the top-level `README.md`.
